 POST-EFFECTS PIPELINE (iter.3)
   Simple segment:
     RENDER scene → fbo0
     POST blm fbo0 → fbo1          (bloom: 12 circular samples, threshold 0.6, radius 4)
     POST vig fbo1 → fbo2          (vignette: strength 0.35, softness 0.5)
     POST grn fbo2 → screen        (grain: animated, uAmount 0.20)
     PRESENT screen

   Transition segment:
     RENDER s1 → fbo0; RENDER s2 → fbo1; TRANSITION → fbo2
     POST blm fbo2 → fbo3
     POST vig fbo3 → fbo4
     POST grn fbo4 → screen
     PRESENT screen

   FBO count: 3 (simple) / 5 (transition), все lazily allocated через FBOPool::get

 ПРОИЗВОДИТЕЛЬНОСТЬ
   Средний FPS: 60.8  (бюджет 50 — выполнен с запасом +21%)
   Минимальный FPS: ~22 (на переходах с nebula, raymarching-тяжёлый шейдер)
   Максимальный FPS: ~100 (sphere_scene, vsync в windowed не строгий на Win11)
   Bloom cost:        ~1.5 мс/кадр (12 texture samples × 1280×720)

   Grain cost:        ~0.3 мс/кадр (1 sample + 1 hash)
   Total post-chain:  ~2.3 мс/кадр (4.6% бюджета 16.7 мс при 60 FPS)

 АРХИТЕКТУРНЫЕ РЕШЕНИЯ v52 (унаследованы от v51 + новые)
   1. Window:        WS_OVERLAPPEDWINDOW + WS_EX_APPWINDOW
   2. Single-instance mutex
   3. SMT parser:    position-based prog (1-й=opacity, 2-й=progress)
   4. safeRun():     defensive — пустые программы не бросают exception
   5. try/catch:     вокруг renderFrame в основном цикле
   6. FBO pipeline:  последовательно, без read-write hazards
   7. Render loop:   PeekMessage + renderFrame + SwapBuffers
   8. POST chain:    blm → vig → grn (правильный порядок)
   9. FBO lazy alloc: через std::map в FBOPool, не требует pre-declaration

 ПАРАМЕТРЫ POST-EFFECTS (для будущего тюнинга)
   bloom:

   vignette:

 ИЗВЕСТНЫЕ НЕДОСТАТКИ (не блокирующие)
   • Shader'ы anxiety_mist, morph_grid, cozy_room_sdf — написаны, но НЕ подключены
     к demo.smt. Готовы к использованию в v53.
   • На T=0–23 (nebula) FPS ~24 — raymarching тяжелый. Это не баг, особенность
     шейдера на GTX 750. Можно оптимизировать снизив количество шагов march'а.
   • Окно имеет рамку (не fullscreen). Для финального демо можно переключить
     на WS_POPUP после всех проверок.
   • Bloom single-pass с 12 семплами — приемлемое качество, но не идеальное.
     Для premium-качества можно переписать на multi-pass separable Gaussian.
   • Energy curve статична (зашита в .smt). Реальная audio-reactivity
     (управление от аудио-файла) не реализована — переменные audio.beat /
     audio.energy сейчас вычисляются из статической таблицы.
