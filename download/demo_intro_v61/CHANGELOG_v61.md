# v61 — что проверено и что исправлено

Дата: 2026-11-11. База: `demo_runtime_v60(7).zip` (в архиве лежал как `demo_intro_v60/`).

Проект собран MSVC 14.43 (VS 2022 Build Tools, `cl /std:c++17 /EHsc /O2 /W3`) без ошибок и
предупреждений, полный прогон 211 с проходит до `[Done]`. Все правки — в этом каталоге,
оригинальные шейдеры сохранены рядом как `*.v60.bak`.

## Найденные дефекты

### 1. PNG-писатель отдавал битые файлы (все PNG из F2/F3)

`writePNG()` писал длину чанка и CRC через `fwrite(&unsigned)`, то есть в little-endian,
а формат PNG требует big-endian. В результате ни один декодер не мог открыть файл:

```
ffmpeg: [png] chunk too big / Decoding error
PIL:    OSError: Truncated File Read   (IHDR length читался как 0x0D000000)
```

Починено: добавлен `putBE32()` для длины и CRC. Проверка — чанки IHDR/IDAT/IEND, CRC и
inflate сходятся (`_pngcheck.py`).

### 2. Хэш шума «умирал» при seed ≥ 22222

```glsl
p = fract(p * 0.3183099 + 0.1) + float(uSeed) * 0.0001;  // seed = 44444 -> +4.44
p *= 17.0;                                                // p ~ 75..92
return fract(p.x * p.y * p.z * (p.x + p.y + p.z));        // произведение ~1.3e8
```

При magnitude ~1e8 шаг float32 равен 8, поэтому `fract()` возвращал ровно `0.0`
для любого аргумента. Численная проверка (`_hash_check.py`):

| seed | clip | произведение | fract(prod) |
|------|------|--------------|-------------|
| 11111 | s1 nebula | 1.1e6 | 0.625 / 0.75 / 0.0 (сетка 1/16) |
| 22222 | s2 | 1.1e7 | 0.0 |
| 44444 | s4 anxiety | 1.3e8 | 0.0 |
| 77777 | s7 | 1.1e9 | 0.0 |

Последствия:

* `grain.frag` (seed 88008): `n = 0` → `col.rgb += (0 - 0.5) * uAmount * 2` — **каждый кадр
  терял 0.2 в sRGB**. Это и была главная причина «слишком темно» на всех сценах.
* `anxiety_mist.frag` (seed 44444): `mist == 0.0` на всём кадре → сцена рисовала не туман,
  а ровный градиент от виньетки (замер: max luminance 0.086, 70% пикселей < 0.05).
* `nebula_raymarch.frag` (seed 11111): шум не ноль, но квантован шагом 1/16 — «блочное» облако.

Починено: `hash3()` переписан на целочисленный: `uint`-смешивание координат
решетки и seed, 24 бита на выходе.

> **v61.1.** Первая версия правки использовала дешёвый `fract`-хэш (seed внутри
> `fract`, произведение ~1e5). Это вернуло скорость, но дало всего ~64 уровня
> шума: после `smoothstep(0.3, 0.7, mist)` уровни превращались в прямоугольные
> ступеньки — в anxiety были видны «квадраты». Возвращено к `uint`-хэшу;
> замеры: anxiety 13.7 мс/кадр (там нет raymarch-цикла), nebula 62 мс/кадр
> при 40 шагах. Квантование было видно и в `grain` — там хэш тоже заменён.

### 3. Color Matrix не работала на volumetric-сценах

Подтверждено замером: `nebula` при базовом цвете (0.05, 0.10, 0.30) давал mean luminance
0.0030 и 100% пикселей темнее 0.05 — сцена была практически чёрной, поэтому любой
mood-цвет из Color Matrix «не читался».

Причина двойная: цвет умножался на density (0.05–0.3) **и** композитился как
`mix(bg, vol.rgb, vol.a)` при `vol.a ≈ 0.08`, то есть 92% кадра оставалось фоном.

Починено в `nebula_raymarch.frag`:

* `colorize()` — хрома/яркость разделены: цвет из Color Matrix задаёт только hue,
  яркость нормируется к `REF_LUMA`. Теперь смена mood-цвета не меняет экспозицию.
* `avgLight = vol.rgb / max(vol.a, 1e-4)` + `cover = 1 - exp(-vol.a * COVERAGE_GAIN)` —
  un-premultiply и remap плотности, чтобы тонкий туман был виден.
* `EXPOSURE` — яркость облака отдельным коэффициентом.

В `anxiety_mist.frag` то же самое: `primaryMod` нормируется через `colorize()` уже
после канального сдвига warm/cold (раньше тёмный primary (0.25, 0.05, 0.1) ужимался
сдвигом до (0.30, 0.024, 0.036)).

### 4. Вспышка anxiety горела 70% времени

`panicFlash()`: `flashMask = step(phase, 0.7)` при периоде 4.6 с — по комментарию в коде
вспышка должна длиться 0.3–0.6 с. В результате сцена была постоянно залита розовым.
Стало: окно 0.12 периода (~0.55 с), спад `pow(..., 2.0) * 0.9`. Замер по циклу:
0.120 → 0.213 → 0.126 → 0.234 (тихо / вспышка).

### 5. `morphing_figures`: небо выжигало кадр

`bg = mix(bgColBottom, bgColTop, bgGrad) * 0.6` при palette `a + b*cos(...)` давало
почти белый фон: mean luminance 0.7024 (p50 0.7311) ещё в исходном v60.
Множитель снижен до 0.15 → mean 0.284, фон стал тёмным, фигура и частицы читаются.

## Что добавлено

* `demo_runtime.exe demo.smt --still 2.0 --out still.png [--repeat N]` — одиночный кадр
  в PNG без шоу-лупа (одна проверка ~1 с вместо 3.5 мин). `--repeat` работает как
  бенчмарк: `--still 2 --repeat 60`.
* `uExposure` в `grain.frag` — глобальная экспозиция в линейном пространстве,
  применяется до зерна, задаётся из `demo.smt` (сейчас 0.55). Нужна потому, что все
  цвета сцен подбирались при баге зерна, которое вычитало 0.2 из кадра.
* `uAmount` зерна снижен 0.2 → 0.03 (при рабочем шуме ±0.2 забивало детали).

`nebula` стал дороже: раньше шум был сломан (`fract == 0`), и цикл шёл по «пустой»
ветке почти без вычислений. Теперь честные 4 октавы × 2 вызова FBM на шаг.
Дешёвый `fract`-хэш возвращал скорость (nebula 34 FPS), но давал «квадраты»,
поэтому оставлен целочисленный вариант.
Бенчмарк одного кадра: `--still 2 --repeat 60` ≈ 37 мс/кадр при 40 шагах.

## Открытые вопросы (нужно решение автора)

1. **Экспозиция.** `uExposure = 0.55` — компромисс, подобранный по замерам, а не
   художественное решение. Если сцены кажутся пересвеченными/тёмными — крутится одним
   числом в `demo.smt` (clip `grn`), без пересборки.
2. **Вид nebula.** Coverage remap (`COVERAGE_GAIN = 4.0`) и `EXPOSURE = 0.75` подобраны
   по «читаемости» кадра. Плотность облака можно вернуть к более редкой, уменьшив
   `COVERAGE_GAIN` — тогда снова появятся тёмные области.
3. **`uMotionSpeed` в anxiety.** По коду он равен 1.5, но сцена почти не двигается:
   туман считается от `t = uTime * uMotionSpeed * 0.3`, а вклад в `fbm` идёт по третьей
   оси — сдвиг за 25 с всего ~11 единиц при масштабе ячейки ~1. Если нужен заметный
   дрейф — поднимать множитель 0.3.
