# Scene Manager для Demo без лимита: Directed Timeline, управляемый GLM

Задача: сделать Scene Manager, с которым GLM может собирать **неограниченное число разных демо** (5–10 минут, готовый MP3, без лимита размера), а главное требование — **гибкость и удобство управления**. Ниже: что я взял из двух присланных документов, что исправил, что построил и проверил, и что остаётся решить вам.

Допущения, которые я принял (поправьте, если не так): «на GLM» значит, что GLM сам авторит и правит демо через инструменты; «unlimited» значит отсутствие лимита размера и отсутствие пересборки C++ под каждое демо.

## 1. Вердикт по присланным документам

| Тезис | Вердикт | Что я сделал |
|---|---|---|
| Perplexity: A–E это уровни одной системы, а не альтернативы | **Верно**, это главная идея | Взял за основу: Directed Timeline + render graph + audio как мастер-время + atom→GLSL + генерация как подготовка |
| Perplexity: uber-shader не нужен в Demo, переход это клип в графе, а не enum в ядре | **Верно** | Переходы и пост — обычные эффекты с манифестами |
| Perplexity: Cozy Engine это ассистент подготовки, а не режиссёр рантайма | **Верно** | Закреплено в модели данных: статус `proposed`/`accepted`, финальная сборка требует утверждения автором |
| Perplexity: `map` с `expr` строками | **Недоопределено**: без грамматики это `eval` | Язык выражений с проверкой, тотальной семантикой и RPN (раздел 5) |
| Perplexity: `from: color_matrix.primary` | **Опасно для детерминизма**: цвет «из матрицы» в рантайме | Палитры **закрепляются** (pinned) в показе вместе с происхождением; рантайм не знает про Color Matrix |
| Perplexity: «AudioClock.beat()/bar()/section()» | **Верно, но GLM не слышит музыку** | Офлайн-анализ MP3: темп, первая доля, энергия, секции, маркеры (раздел 6) |
| GLM: расчёт под 4K/64K, экономия байтов | **Нерелевантно для Demo** | Не используется |
| GLM, вариант D: Python-генератор «embed C++ struct в binary» | **Противоположно гибкости**: каждое демо = пересборка | Демо это данные (`demo.show.json` → `demo.smt`), движок не пересобирается |
| GLM, вариант E: FBO на каждый слой | Платить за это не нужно | План проходов с выделением FBO по времени жизни (раздел 7) |
| В документах «atom» значит три разных вещи | **Путаница** | Разведены (раздел 2) |

### Три значения слова «atom» (стоит договориться)

1. В документе GLM «atoms» — **шейдерные единицы** (`nebula_raymarch`, «64 atoms ≈ 50 КБ шейдеров»).
2. В документе Perplexity «atoms» — **управляющие параметры** (`feel`, `energy`, `temperature`).
3. В моём Cozy Engine «atoms» — **словарь объектов интерьера** (`sofa`, `rug`, `lamp`).

В реализации: шейдерная единица называется **эффект** (effect), управляющий параметр — **атом** (как у Perplexity), а словарь Cozy Engine остаётся его внутренним делом. Важное следствие: **Cozy Engine не умеет подбирать шейдеры по настроению**, он ничего не знает про туманности. Его реальный вклад в демо — объекты и примитивы для 3D-сцены (раздел 9).

## 2. Архитектура

```
  GLM ──(инструменты)──▶ ShowSession ──▶ demo.show.json   (исходник: его правят человек и GLM)
                              │
                       compile │ (якоря → секунды, атомы → программы, проверки)
                              ▼
                        ResolvedShow ──▶ render graph (проходы, FBO)
                              │ bake
                              ▼
                  demo.baked.json + demo.smt  ──▶  C++ рантайм (только исполнение)
```

- **Исходник** — данные. Новое демо это новый `show.json` и, при необходимости, новый эффект (шейдер + манифест). Движок не пересобирается.
- **Компилятор** собирает все ошибки за один проход, с путём к проблеме. Рантайм не может встретить неразрешённую ссылку.
- **Запечённый файл** содержит только абсолютные времена, константы и RPN-программы от `t`, `p`, `dur`, `time`, `audio.*`. Поэтому рантайм детерминирован, любое `T` можно «перемотать» точно, Python и LLM в рантайме не нужны.
- **Рантайм** исполняет готовый план проходов. Правила композитинга живут в одном месте (планировщик), а не в C++.

## 3. Модель данных (что видит автор)

```jsonc
{ "format": "scene-manager/1",
  "meta":   { "duration": "auto", "resolution": [1920,1080], "fps": 60, "seed": 2026, "budget": 14 },
  "audio":  { "bpm": 128, "offset": 0.352, "markers": [ {"name":"drop1","bar":33}, {"name":"end","bar":193} ],
              "analysis": "soundtrack.analysis.json" },
  "palettes": { "cozy": { "primary":"#c88484", "accent":"#…", "bg":"#…", "text":"#…", "_source": {…Color Matrix…} } },
  "looks":    { "cozy": { "palette":"cozy", "atoms": {"temperature": 3} } },
  "tracks":   [ {"id":"main","order":10}, {"id":"post","order":25}, {"id":"overlay","order":30} ],
  "assets":   { "living_room": { "layout":[…], "floats":[…] } },
  "clips": [
    { "id":"drop1a", "track":"main", "kind":"scene", "effect":"nebula_raymarch",
      "start":{"marker":"drop1"}, "end":{"marker":"drop1","offset_bars":20},
      "look":"euphoric", "atoms":{"energy":{"expr":"0.4 + 0.8*audio.energy"}} },
    { "id":"t1", "kind":"transition", "effect":"crossfade", "between":["drop1a","drop1b"], "duration":{"beats":4} } ] }
```

**Якоря времени.** Время клипа задаётся не секундами, а привязкой: `{marker, offset}`, `{bar, beat}`, `{end_of|after: клип}`, `{start_of|with: клип}`, со смещением в секундах, долях или тактах; длительность — число, `{beats}`, `{bars}` или `{until: якорь}`. Сдвинули маркер, поменяли BPM или длину клипа, и всё, что на них опирается, пересчитывается само; клипы с абсолютным временем остаются на месте.

**Переходы — связи, а не клипы на таймлайне.** `between:[A,B]`, длительность, `align: center|end|start`, кривая. Менеджер сам продлевает A и B на время окна перехода («подводка», как в видеоредакторе), поэтому автору не нужно вручную перекрывать клипы. Номинальное окно клипа остаётся тем, что задал автор.

**Атомы и кривые.** Атом: число, bool, строка (категория, например `feel`), `{expr: …}` или `{keys:[[t,v,ease?],…]}`. Кривые разворачиваются в выражение без вложенности (до ≈1400 ключей; до 100 ключей совпадение с `numpy.interp` 1e-15). В запечённом файле атомов уже нет: они подставлены в программы.

**Манифест эффекта** задаёт uniform'ы (тип, диапазон, умолчание), **`bind`** — привязку по умолчанию («`uMotionSpeed` = `0.6 + energy*0.8`», «`uPrimaryColor` = `palette.primary`»), значения атомов по умолчанию, `suits` (для каких настроений), `cost`, `direct_blend`, `text`. Клип переопределяет только то, что отличается. Поэтому клип в примере занимает 5–6 строк.

**Типы uniform:** `float`, `int`, `bool`, `vec2/3/4`, `farray` (константный массив чисел: примитивы Cozy Engine).

## 4. Чем это удобно управлять (ради чего всё сделано)

| Возможность | Что даёт |
|---|---|
| Якоря, маркеры, музыкальные единицы | Перемонтаж одной правкой. В примере: `drop1` с такта 33 на 37 сдвинул 2 клипа на 7,5 с, а `room`, `credits`, `bloom` остались на месте |
| Переходы как связи с автоподводкой | Не нужно считать перекрытия |
| Манифесты эффектов + `bind` + атомы по умолчанию | Новый эффект без правки C++; клипы короткие; GLM читает каталог и знает допустимые параметры и диапазоны |
| Палитры и `look`'и | Смена настроения секции — одна правка: `look cozy → палитра calm` перекрасила комнату (`uLightColor.r` 0,318 → 0,898) |
| Пакетная атомарная правка `edit_show` | Либо все операции, либо ни одной; возвращается diff замечаний |
| JSON merge-patch в `update_clip` | Правка одного атома = одна короткая операция; `null` удаляет ключ |
| Undo/redo, `dry_run`, `require_valid` | Безопасные эксперименты |
| `locked` и `proposed/accepted` | Утверждённое автором не трогает генератор; финальная сборка (`strict`) требует утверждения всех клипов |
| `show_overview` (раскадровка с тактами и секциями), `resolve_at(t)` | GLM «видит» показ без GPU: что активно, какие значения, какие проходы |
| Линт | 35 кодов замечаний: 21 ошибка, 10 предупреждений, 4 справочных (ниже) |

**Что ловит линт:** ссылки на несуществующие эффекты/дорожки/маркеры/клипы, циклы якорей и атомов, переход длиннее клипов, перекрытия и пробелы на дорожке, чёрные кадры (нет сцены), клип за концом показа, обязательные uniform'ы без значения, зарезервированные имена, выход значений за `[min,max]` манифеста (выборка по 33 точкам клипа), бюджет стоимости эффектов, контраст `text/bg` у текстовых эффектов (WCAG 4,5:1), неоднозначные массивы, ошибки выражений.

## 5. Язык выражений

Числа, имена (`audio.energy`), `+ - * / %`, сравнения, `&& || !`, функции: `abs sign floor ceil fract sqrt sin cos exp min max pow mod step clamp mix smoothstep if`. Нет циклов, присваиваний, строк. **Все функции тотальны:** деление на ноль даёт 0, `sqrt(<0)` = 0, `pow(<0, дробь)` = 0, результат всегда конечен. Длина авторского выражения до 200 токенов. Выражение компилируется в RPN, которую исполняет стековая машина (в C++ около 110 строк вместе с операторами и функциями). Переменные: `t` (секунды от номинального начала клипа, на подводке отрицательные), `p`, `dur`, `time`, `audio.beat`, `audio.beat_phase`, `audio.bar`, `audio.bar_phase`, `audio.energy`, `audio.section`.

## 6. Музыка

`AudioMap` — чистые функции времени (доля, такт, фаза, маркеры по тактам). `analyze_audio` декодирует MP3/WAV (ffmpeg) и даёт GLM данные, которых он не может «услышать»: темп, первую долю, огибающую энергии, границы секций, предложенные маркеры.

Измеренная точность (**на синтетических треках с известной структурой**):

| Проверка | Результат |
|---|---|
| 32 трека (4 темпа × 4 сдвига × с хэтами и без) | темп ±0,01 BPM, первая доля ±8 мс |
| MP3 (декодер ffmpeg), 6-минутный трек | 128,0 BPM, первая доля 0,352 с (истина 0,35) |
| Границы секций | 6 из 6 и 3 из 3 с верными ярлыками (build/drop/breakdown/outro), ложных нет |

Что пришлось исправить по ходу: сетка садилась на офбитные хэты (фазу теперь ищет низкая полоса, где кик), темп «плыл» на 1,2 BPM (добавлено уточнение совместным поиском), короткие 8-тактовые подъёмы пропускались (два масштаба новизны), ярлыки зависели от абсолютной энергии (пороги стали относительными).

**Оговорки:** пороги подбирались, пока синтетическая структура не восстановилась, на реальной музыке это **не проверено**. Темп считается постоянным (для переменного темпа задавайте маркеры вручную). Секции без перепада энергии не видны (в примере `climax` на такте 153 по построению не отличается от соседней секции). Первую долю и маркеры нужно проверить на слух.

## 7. Граф рендера

Правила (один источник истины — планировщик; рантайм исполняет готовый план):

- дорожки идут снизу вверх; первая непрозрачная сцена рисуется **прямо на экран**, без FBO;
- эффект с `direct_blend` (частицы, вспышки, титры) рисуется в накопитель с GL-смешиванием, без своего FBO;
- переход читает A и B (каждый в своём FBO) и пишет результат, а если он первый слой, то сразу на экран;
- **post обрабатывает всё, что ниже его дорожки**, а то, что выше, рисуется после: титры остаются чёткими, не попадая под bloom;
- цепочка из любого числа post использует 2 текстуры (пинг-понг); физические текстуры выделяются по времени жизни.

Проверено: интервалы жизни одной физической текстуры не пересекаются (тест на всех сегментах), одиночная сцена даёт 0 FBO, три post дают 2. В 6-минутном примере **20 сегментов, пик 3 FBO ≈ 49,8 МБ** (1080p, RGBA16F, это допущение) на 0,5 с в момент перехода под post.

## 8. Запечённый формат и C++ рантайм

`demo.baked.json` — канон; `demo.smt` — плоский текст из токенов без пробелов, который C++ читает без JSON-библиотек (пример показа: 77 КБ и 56 КБ, исходник 15 КБ). `runtime_ref/sm_runtime.hpp` (253 строки, C++17, без GL и зависимостей) — **эталон исполнителя**: стековая машина, загрузчик, поиск активных клипов и сегмента по времени, вывод значений.

Проверка соответствия C++ ↔ Python (оба обязаны давать одно и то же):

- фаззинг: 250 случайных выражений (все 15 операторов и 18 функций, краевые случаи) × 40 моментов времени, **> 8000 значений без расхождений** (отдельный прогон 400 × 52: 18 941 значение, расхождений 0);
- полное 6-минутное шоу в 114 точках (все границы клипов ±1e-4): значения, список активных клипов, массивы, план проходов, вывод совпал построчно (0 расхождений из 597 строк); эталон собирается с `-Wall -Wextra -pedantic -Werror` без предупреждений;
- **мутационная проверка** самого теста: 9 намеренных порч C++ (swap `mix`, `step`, `mod`, граница клипа/сегмента, интерполяция энергии, индекс секции…): 7 пойманы, 2 «не пойманы» (`pow` для отрицательной базы и деление на ноль) оказались эквивалентными мутантами, потому что `fin()` превращает NaN/inf в 0; контроль без порчи проходит.

Рантайму остаётся: GL-исполнение проходов, загрузка шейдеров по `effect` и привязка uniform'ов по имени из манифеста, предкомпиляция по `prewarm_start`, остановка по `finish`.

## 9. Связь с Color Matrix и Cozy Engine

**Color Matrix** даёт цвета, empathy, intensity, температуру и контраст. Инструмент `suggest_palette(feel, temperature?)` строит палитру ролей `primary/accent/bg/text` (контраст `text/bg` ≥ 7:1), и её **закрепляют** в показе вместе с происхождением (`_source`: версия, запросы). Рантайм Color Matrix не знает.

> **Ловушка, найденная при сборке примера.** `feel=warmth` в Color Matrix означает «безопасность, мягкий позитив» (синий (37,99,235) там +22), а **не тёплый цвет**: «уютная» палитра вышла голубой. Поэтому у `suggest_palette` добавлен отдельный параметр `temperature` (warm/cool), а в описании инструмента и в политике для GLM это сказано явно. Кроме того, при проверке Cozy Engine я не нашёл у эмпатии Color Matrix эмпирического подтверждения (AUC 0,49–0,55 внутри типа комнаты), так что используйте её как гипотезу, а палитры утверждайте глазами.

**Cozy Engine** отвечает за объекты и их форму. Путь: `cozy_scene_plan` → расстановка (`build_cozy_asset`, с проверкой границ комнаты и пересечений) → ассет из примитивов (12 чисел на примитив: форма, ось, размер, позиция, поворот, цвет) → uniform-массив `farray` SDF-эффекта (`uPrimitives`; рантайм должен задавать и `uPrimitivesCount`) → запекание → рантайм. В примере комната из 32 примитивов проходит весь путь, включая C++. Цвета слотов приходят из Color Matrix (`cozy_palette`).

Чего Cozy Engine здесь **не делает**: не выбирает эффекты и переходы по настроению (для этого у эффектов есть `suits`, а у `suggest_transitions` эвристика по перепаду энергии музыки на стыке).

## 10. Что даёт GLM

12 инструментов Scene Manager (`show_overview`, `edit_show`, `lint`, `resolve_at`, `list_effects`, `describe_effect`, `history`, `analyze_audio`, `suggest_palette`, `suggest_transitions`, `build_cozy_asset`, `bake`) + инструменты Color Matrix и Cozy Engine в одном наборе (`FullToolbox`, имена не пересекаются). Рабочий цикл и правила — `policy/scene_policy.md`. `examples/build_demo.py` строит 6-минутное демо **только вызовами этих инструментов** (24 клипа, 10 сцен, 9 переходов, пост, титры, finish), `lint` ошибок 0, предупреждений 0.

## 11. Что проверено, а что нет

| Проверено автоматически (144 теста в проекте, 71 на Scene Manager) | Не проверено |
|---|---|
| Выражения, тотальность, RPN; кривые до 1500 ключей | **Любой GL/GLSL**: нет GPU, шейдеров эффектов в поставке нет (только манифесты) |
| Якоря, переходы (все `align`), каскады ошибок, лимиты, ассеты | **Реальная музыка**: анализ проверен на синтетике; настройки подбирались под неё |
| Граф: 0 FBO без post, 2 при цепочке, непересечение жизни текстур | **Поведение GLM с этими инструментами**: модель не запускалась |
| Сессия: атомарность, merge-patch, undo, блокировки, ripple, strict | Сборка C++ под MSVC/Windows (проверен g++ 13 на Linux) |
| C++ = Python: фаззинг, полное шоу, мутации | Скорость на шоу в тысячи клипов (не мерилась) |
| Линт примера: 0 ошибок, 0 предупреждений | Конвенция `<имя>Count` для `farray` в GL |

Эвристики и допущения: пороги анализа музыки; правила `suggest_transitions` (flash/glitch при росте энергии, fade при спаде); `cost` эффектов 1–5 условный; память FBO считается как 1080p RGBA16F; корректность `direct_blend` держится на том, что эффект выдаёт премультиплицированный цвет без чтения подложки.

**Дефекты, найденные и исправленные уже по ходу работы** (чтобы вы знали, где было слабо): кривые с ≥ 10 ключей не компилировались (лимит 200 токенов); бейкер округлял энергию, и C++ расходился с Python на нерегулярных данных; `suggest_palette` давал синий «тёплый» цвет; три ошибки собственного примера (углы за допустимым диапазоном, чёрный кадр 0,35 с до первой доли) поймал линт.

## 12. Решения за вами

1. **Загрузка в рантайм:** брать `.smt` (без зависимостей, 253 строки эталона) или JSON-загрузчик вашего проекта? Формат один, но от этого зависит первый шаг интеграции.
2. **Строковые параметры** (текст титров): в формате v1 их нет. Предлагаю ассет-текстуру/атлас (как `farray`, только данные); нужно ваше решение, как рендерить титры.
3. **Переменный темп:** достаточно ли постоянного BPM + ручных маркеров, или нужна карта темпа?
4. **Конвенция стыка перехода:** стык берётся по началу B, окно по умолчанию по центру стыка. Если вам привычнее иначе (например, по концу A), это меняется в одном месте.
5. **Терминология:** согласны ли с «эффект / атом / примитив» вместо трёх значений «atom»?

## 13. План внедрения

1. **Рантайм-ядро:** загрузка `.smt`, часы от аудио, активные клипы, одна сцена и CUT (эталонный C++ подходит как есть).
2. **Исполнение плана:** проходы RENDER/DRAW/COMPOSITE/TRANSITION/POST, пул FBO (`fbo0…`, `screen`).
3. **Эффекты как плагины:** загрузка `.frag` по `effect`, привязка uniform'ов из манифеста, предкомпиляция всех шейдеров при загрузке с запасным эффектом при ошибке (одна ошибка GLSL не должна ронять показ).
4. **`farray` и титры** (решение 2).
5. **Замер:** прогнать GLM на 10–20 заданиях «собери демо под этот MP3» с инструментами и без, оценить вслепую; только это покажет, помогает ли такой набор на деле.
