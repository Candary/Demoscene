# Color Matrix v11 + Cozy Engine + Scene Manager — цвет, уют и монтаж демо для LLM (GLM)

> **Новое: Scene Manager** (Directed Timeline для демо без лимита размера, управляется GLM) описан в `SCENE_MANAGER.md`; политика для модели — `policy/scene_policy.md`; пример 6-минутного демо — `examples/` (`python examples/build_demo.py`); эталон C++ рантайма — `runtime_ref/`.
>
> **Новое: Cozy Engine** (объекты и примитивы сцены, связанные с Color Matrix) описан в `COZY_ENGINE.md`; политика для модели — `policy/cozy_policy.md`. Данные: `output/cozy_data/`.

Что это: исходный проект (NPZ с профилями 16 777 216 цветов + ридер) дополнен тем, чего не хватало, чтобы модель могла **сама решать, где и когда применять цвет**: исправлениями данных, обратным поиском, инструментами для function calling, политикой решений и набором задач оценки.

## Быстрый старт

```bash

```

## Что показал анализ v10

| Находка | Следствие |
|---|---|
| Температура зависит только от тона; серые получали `hot`, почти-серые (разброс каналов 1–2) — случайные значения | **Исправлено в v11** (237 349 ячеек, 1,4%) |
| Энтропия на 99,6% определяется парой (S, L), тон не учитывается; средний серый имел метку `very_dark` | Метки переименованы в intensity-шкалу (числа не менялись); в политике: по энтропии читаемость не оценивать |
| Эмпатия примерно на 94% объясняется тройкой (H, S, L); 2,4% цветов (светлые тёплые) упёрлись в +100 | Поиск целится в 80, а не в 100, чтобы не выбирать случайно из плато |
| Шесть синестетических измерений — производные от H/S/L; у `spatial_depth` в данных 5 уровней, в документе 4 слова; порядок слов `texture` не совпадает с данными | Слова подставляются только там, где порядок подтверждён; для `texture` и `spatial_depth` отдаётся уровень и `driver` |
| 76% цветов получили метку `neutral`; всего 460 уникальных синестетических комбинаций | Матрица различает «тёплое/холодное», «светлое/тёмное», «яркое/тусклое», тонких различий не несёт |

Итог: матрица — аккуратно версионированный контракт на формулы «H/S/L -> ощущение». Ценность — единый воспроизводимый язык и точка, куда позже придут crowd-данные. Это не знание о людях, и модели явно сказано об этом (`confidence` номинальный, `provenance` в каждом ответе).

## Что добавлено

| Компонент | Зачем |
|---|---|
| `search.py` — `find_colors` | Обратный поиск: «ощущение + оттенок/светлота/chroma + контраст с фоном» -> разнообразные реальные цвета; при пустом результате возвращает `diagnostics`, где ограничение «обвалило» выбор |
| `tools.py` — 5 инструментов | `describe_color`, `find_colors`, `check_contrast` (с предложением исправления), `build_palette`, `check_palette` (в т.ч. симуляция дальтонизма) |
| `policy/color_policy.md` | Порядок решений: заданное -> доступность -> конвенции -> эмоция по матрице; когда **не** вызывать инструменты |
| `agent.py` | Цикл tool-calling для OpenAI-совместимого клиента |
| `eval/` | 12 задач (UI, графики, настроение, бренд, 3 задачи на воздержание) с объективными проверками |

Контраст, различимость и дальтонизм **измеряются**, а не «чувствуются»: их нельзя оценить интуицией, а ошибки здесь бьют по пользователю сильнее всего.

## Что сознательно не менялось

- Формулы энтропии и эмпатии. Замена одной выдуманной формулы другой без данных не добавляет знания. Ограничения вынесены в политику и предупреждения.
- Слова `texture` и `spatial_depth`: нужно решение владельца словаря.
- `emotional_opposite`: определение неоднозначно; пробная реализация давала неубедительный результат (противоположностью красного оказывался светлый красный). Удалена, ждёт формулировки и тест-примеров.

## Ограничения этой поставки

- **Не проверено на настоящем GLM.** Без сети цикл агента проверен только скриптованным клиентом. Схемы инструментов в формате OpenAI/GLM `tools`; их реальное поведение с вашей версией GLM нужно проверить.
- **Оценка не прогонялась на модели.** Харнесс проверен: эталоны проходят, случайные цвета проваливаются. Эталонные решения доказывают выполнимость задач, но не являются образцами дизайна.
- Эмоциональное соответствие автоматически не проверяется (оценивать матрицей саму матрицу было бы круговой проверкой); для этого в задачах есть `human_rubric`.
- Пороги температуры (0.01/0.03), допуск эмпатии (10) и значения `PRIOR_CONFIDENCE` — инженерные эвристики, а не измерения.
- Модули `ingest` и `blender` из документации в поставку не входили и не реализованы.

4. Запустить сбор crowd-данных: только они превратят prior в знание.
