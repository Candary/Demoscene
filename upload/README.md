# Demo Intro v2 — Морфящиеся 3D-фигуры с объёмными частицами

Красивое демо-интро на чистом C++ с OpenGL 3.3, без внешних библиотек.
Чистый Win32 API + OpenGL, никаких SDL/Glfw/Glew — только Windows SDK
или MinGW, который у тебя уже есть.

## Что делает интро (версия 2)

При запуске ты увидишь полноэкранное окно, в котором:

- **9 морфящихся 3D-фигур** плавно перетекают между собой по кругу:
  сфера → куб → тор → октаэдр → **треугольник** → **конус** → **капсула** → **чайник** → **додекаэдр** → снова сфера
- **Неоновая палитра магента-циан-лайм** в стиле кибер-синтвейв
  (другая, чем в v1 — больше насыщенных переливов)
- **8 объёмных частиц** — это настоящие 3D-сферы, которые парят
  вокруг главной фигуры по разным орбитам. Каждая частица имеет
  свой «характер» (через хеш-функцию от ID):
  - **Светящиеся (emissive)** — яркость > 1.0, перегорают в ACES,
    добавляют к bloom-эффекту, пульсируют «вдох-выдох»
  - **Полупрозрачные (translucent)** — alpha 0.25–0.6, смешиваются
    с фоном, имеют rim-свечение по краю (как у стеклянного шарика)
  Когда частицы пролетают близко к фигуре, они **smin-сливаются с ней**
  — даёт эффект живого метабола
- **Градиентный фон** с переливами по палитре Иниго Квилеса
- **Звёздное поле** — мерцающие точки на далёком небе
- **Динамическое освещение**: диффуз + specular + ambient, свет вращается
- **Bloom-имитация**, виньетка, ACES-тонмаппинг, гамма-коррекция
- **Стекающие капли дождя** по экрану с эффектом **мокрого стекла**:
  - **Круглые активные капли** — преломляют фон через повторный raymarch
    (видно смещённую сцену внутри капли, как через линзу), + specular-блик
    сверху-справа
  - **Trail-след** — короткая полоса прямо под каплей (где вода стекает)
  - **Мокрый путь** — длинный след от старта капли до её текущей позиции,
    экспоненциально затухает (имитация испарения), с шумными волновыми
    краями, слабым преломлением и тёмным мениском
  - **Merцание** — лёгкие блики света на водяной плёнке
  - Гравитационное ускорение капли к низу
- **Анимированный огонь на частицах воды**: иногда одна из 8 водяных
  сфер «загорается» — на её месте появляется **процедурный мульти-
  партикльный огонь** (30 мелких частиц со своими lifetime/velocity/
  offset/phase, циклят через `mod(t+phase, lifetime)` — непрерывная
  анимация). Сама частица воды скрывается. Без текстуры — цвет и
  форма полностью процедурные во фрагментном шейдере.
  - Появление: раз в 2–4 с случайно выбранная частица, длительность
    3.5 с, максимум 3 одновременно
  - **Билборд-квад** на партикл в world-позиции частицы, ориентирован
    на камеру через её `right`/`up` векторы; проекция повторяет логику
    raymarch-камеры (`clip = (uv.x/aspect, uv.y) * 2`)
  - **uFireUp = normalize(uFirePos)** — партиклы летят радиально
    наружу от центра сцены, разброс по осям ±0.18, скорости 0.15–0.45
  - **Размер партикла** падает квадратично с возрастом
    (`size = uFireSize * (vLife² * 0.5 + 0.15)`)
  - **Цветовой градиент по возрасту**: жёлто-белое ядро (родился) →
    жёлтый → оранжевый → тёмно-красный (умирает). Alpha = exp(-d²·4)
    — мягкие круглые края, минимальное перекрытие между частицами
  - **Аддитивный блендинг** (`gl.SRC_ALPHA + gl.ONE`) даёт неоновое
    свечение; **fade in/out** (0.4 с / 0.5 с) — плавное появление и
    исчезание на уровне источника
  - Подход вдохновлён уроком Chinedufn (particle billboard), но без
    текстурного атласа — полностью процедурный
- **Зум**: колесо мыши или клавиши `+`/`-`/`0` (сброс)

Управление:
- `ESC` — выход
- `SPACE` — пауза анимации (рендер не останавливается — сцену можно крутить мышью)
- `ЛКМ + drag` — вращение сцены (работает в любой момент, в т.ч. на паузе; оси выровнены по экрану)
- `F1` — показ/скрытие FPS в заголовке окна
- `F2` — медленный режим (0.25× скорости) для разбора эффектов
- `+` / `-` (или numpad `+` / `-`) — зум ±15%
- `Колесо мыши` — плавный зум (вверх — ближе, вниз — дальше)
- `0` (или numpad `0`) — сброс зума в 1.0×
- `D` — вкл/выкл эффект стекающих капель (по умолчанию включён)
- `F` — вкл/выкл огонь на частицах воды (по умолчанию включён)
- `Q` — переключить качество (full ↔ 0.7× разрешение — для слабых GPU)

## ⚡ Производительность

Оптимизации, применённые в этом интро:
- **Lazy SDF eval**: MapScene вычисляет только 2 нужные фигуры из 9 (по
  текущей фазе морфинга) — экономит ~370 SDF-вызовов на пиксель.
- ~~Bounding-sphere skip в цикле частиц~~ — **ОТКАТ**: пропуск далёких
  частиц давал овершут raymarch (шаг ~1.0 перепрыгивал сферу с окном
  ~0.84) — частицы воды исчезали из кадра. sqrt на GPU почти бесплатен.
- **RayMarch 60 → 48 шагов** (полный), **30 → 20 шагов** (coarse для
  преломления в каплях).
- **DropletEffect 12 → 8 капель** — меньше хеш-вызовов на пиксель.
- **Fire particles 30 → 20** — достаточно плотно для визуала, меньше
  геометрии на draw call.
- **Cap DPR до 1** — на HiDPI/Retina дисплеях рендер был в 4× больше
  пикселей, теперь 1× (текст чуть мягче, но FPS стабилен).
- **Q key** — экстренное снижение до 0.7× разрешения, если GPU всё ещё
  не тянет (визуально почти не отличается, FPS должен подскочить).

Если после обновления файлов картинка не изменилась — браузер мог
закэшировать старую версию (file:// кэшируется агрессивно). Нажми
**Ctrl+F5** (жёсткое обновление) или открой файл с параметром:
`preview.html?v=2`.

Зум ограничен диапазоном **0.3× — 2.5×**, чтобы камера не ушла
ни в бесконечность, ни внутрь фигуры (при зуме 2.5× камера у самой
поверхности — хороший close-up).

## Требования

Windows 7 или новее. Поддержка OpenGL 3.3 есть в любом GPU, выпущенном
после 2010 года (NVIDIA, AMD, Intel HD Graphics). Драйверы должны быть
обновлены — без них получится "софтверный" OpenGL от Microsoft, который
не потянет современные шейдеры.

## Сборка — способ 1: MinGW-w64 (проще всего)

1. Установи MinGW-w64:
   - Самый простой путь — скачать MSYS2 (https://www.mingw-w64.org/) и
     выполнить: `pacman -S mingw-w64-x86_64-gcc`
   - Или взять готовый билд: https://github.com/niXman/mingw-builds-binaries/releases
   - После установки проверь, что `g++ --version` работает в cmd.

2. Открой cmd в папке с проектом и запусти:
   ```
   build_mingw.bat
   ```

3. Получишь `demo_intro.exe`. Запусти его.

## Сборка — способ 2: Visual Studio (MSVC)

1. Установи Visual Studio 2022 Community (бесплатно):
   https://visualstudio.microsoft.com/downloads/
   При установке выбери "Desktop development with C++".

2. Открой "x64 Native Tools Command Prompt for VS 2022" из Start Menu.
   Это командная строка, в которой настроен PATH на cl.exe и link.exe.

3. Перейди в папку проекта (командой `cd`) и запусти:
   ```
   build_msvc.bat
   ```

4. Получишь `demo_intro.exe`. Запусти его.

## Как модифицировать

Все визуальные эффекты — в файле `shaders.h`, в `kFragmentShaderSrc`.
Открой его в редакторе и попробуй:

### 1. Изменить скорость морфинга

В функции `MapScene` найди строку:
```glsl
float phase = mod(t * 0.25, 9.0);
```
Увеличь `0.25` до `0.5` — фигуры будут сменяться вдвое быстрее.
Увеличь `9.0` до `10.0` и добавь ещё одну фигуру в if-else.

### 2. Изменить палитру

В функции `Palette` можно поиграть с параметрами:
```glsl
vec3 c = vec3(2.0, 1.0, 1.5);   // частоты по R, G, B
vec3 d = vec3(0.0, 0.25, 0.5);  // фазы по R, G, B
```
- `c = vec3(1.0, 1.0, 1.0)` даст "радужную" палитру (как v1)
- `d = vec3(0.5, 0.1, 0.7)` — тёплая оранжево-пурпурная
- `c = vec3(3.0, 1.0, 0.5)` — больше красных переливов

Больше примеров: https://iquilezles.org/articles/palettes/

### 3. Добавить ещё одну фигуру

В `MapScene` добавь свою SDF-функцию (формулы есть на
https://iquilezles.org/articles/distfunctions/), затем впиши её
в морфинг. Так в цепочку добавлен треугольник (октаэдр →
треугольник → конус): призма стала `d5`, а конус сдвинулся в `d6`:
```glsl
float d5 = sdTriPrism(p, vec2(1.0, 0.5));  // треугольная призма
// ... в if-else добавь:
// } else if (idx < 3.5) {
//     d_main = mix(d4, d5, frac_);   // октаэдр → треугольник
// } else if (idx < 4.5) {
//     d_main = mix(d5, d6, frac_);   // треугольник → конус
```
И увеличь счётчик в `mod(...)` на единицу — сейчас `9.0`, по числу фигур.

### 4. Изменить поведение частиц

В цикле `for (int i = 0; i < 8; i++)` можно:
- Изменить `8` на `16` — больше частиц (но raymarching станет медленнее)
- Изменить `radius = 1.6 + 0.4 * sin(...)` — другой разброс орбит
- Изменить `pr = 0.08 + 0.04 * sin(...)` — другой размер частиц
- Изменить параметр `0.15` в `smin(d_main, d_part, 0.15)` — сила слияния
  частиц с телом (больше — мягче, меньше — резче)

### 4.1 Изменить тип частиц (emissive vs translucent)

В блоке `if (hit.y >= MAT_PARTICLE)` каждая частица получает свой «характер»
через хеш-функцию:
```glsl
float rndType = hash(pid * 7.3 + 1.0);   // 0..1
// Если rndType > 0.5 — частица СВЕТЯЩАЯСЯ, иначе — ПОЛУПРОЗРАЧНАЯ
```
- Поменять порог `0.5` на `0.7` — большинство частиц станут прозрачными
- Поменять формулу `glow = 1.5 + 1.0 * pulse` на `3.0 + 2.0 * pulse` —
  светящиеся частицы станут ярче (сильнее «перегорают» в ACES)
- Поменять `alpha = 0.25 + 0.35 * pulse` на `0.5 + 0.4 * pulse` —
  прозрачные частицы станут более плотными
- Чтобы все частицы были только emissive: `if (rndType > -1.0)` (всегда true)
- Чтобы все были только полупрозрачными: `if (rndType > 1.0)` (всегда false)

### 5. Изменить зум по умолчанию

В `main.cpp` найди:
```cpp
static float  g_zoom = 1.0f;
```
Поставь `0.7f` — стартовая камера будет дальше от фигуры.

### 6. Изменить поведение капель дождя

Эффект капель описан в функции `DropletEffect`. Можно:
- Изменить `12` в цикле на `24` — больше капель
- Изменить `0.05 + 0.12 * hash(...)` — диапазон скоростей капель
- Изменить `0.010 + 0.012 * hash(...)` — диапазон радиусов
- Изменить `0.04` в `dir * strength * 0.04` — силу преломления активной капли
- Изменить `0.04 + 0.16 * hash(...)` — диапазон длины trail-следа

### 7. Изменить поведение мокрого пути (эффект мокрого стекла)

В блоке «3. МОКРЫЙ ПУТЬ» функции `DropletEffect`:
- Изменить `0.25 + 0.25 * hash(...)` — диапазон длины мокрого пути (больше — длиннее следы)
- Изменить `exp(-distNorm * 2.5)` — скорость испарения (больше — быстрее высыхает)
- Изменить `* 0.30` — максимальную мокроту пути (0..1)
- Изменить `0.9 + waveAmp * sin(verticalDist * 40.0)` — ширину и «волнистость» краёв
- В main(): изменить `col *= 1.0 - 0.20 * wetness;` — насколько тёмной будет мокрая зона
- В main(): изменить `0.05 * wetness * sin(...)` — силу мерцания водяной плёнки

Можно отключить мокрый путь, закомментировав весь блок «3. МОКРЫЙ ПУТЬ» —
тогда останутся только активные капли и короткий trail.

## ⚡ Оптимизации производительности

Демо оптимизировано для плавного рендера даже на слабых GPU.

### Оптимизация 1: Precompute Rot2D матрицы
Матрицы вращения вычисляются один раз в `RenderScene` (перед raymarch) в
глобальные переменные `gRotXZ/gRotYZ/gRotXY`, а не в каждом вызове
`MapScene` (который вызывается ~60 раз на пиксель в raymarching + 6 раз в
`CalcNormal`). Экономия: ~400 sin/cos вызовов на пиксель.

### Оптимизация 2: Bounding sphere check
Перед детальным raymarching проверяем пересечение луча с bounding sphere
(радиус 2.2) вокруг центра через дискриминант квадратного уравнения. Если
луч мимо — сразу рисуем фон, не тратя 60 шагов. Экономия для пикселей на
краях экрана (где только фон и звёзды).

### Оптимизация 3: Fewer raymarch steps
80 → 60 шагов в `RayMarch`. На ~25% быстрее raymarch.

### Оптимизация 4: Fewer hash calls in DropletEffect
5 hash → 2 hash на каплю через переиспользование сид-значений (h1/h2)
для разных параметров через `fract()`.

### Оптимизация 5: mix() вместо smin() для морфинга
`mix(d_a, d_b, frac_)` дешевле, чем `smin(d_a, d_b, k * frac_)`, и даёт
более предсказуемый переход между фигурами (smin при k=0 вырождается в
min(a,b), что не работает, когда одна фигура содержит другую — например
сфера содержит чайник).

### Оптимизация 6: Precompute частиц в глобальные массивы
Позиции и радиусы 8 частиц вычисляются ОДИН РАЗ в `RenderScene` и
сохраняются в глобальные массивы `gParticlePos[8]` и `gParticleRad[8]`.
Раньше для каждой из 8 частиц вычислялись 3 sin/cos на КАЖДЫЙ вызов
MapScene (60 шагов × 8 частиц × 3 = **1440 sin/cos на пиксель**). Теперь
— только 24 sin/cos на пиксель (8 частиц × 3 sin/cos × 1 раз).

### Оптимизация 7: Tetrahedron trick в CalcNormal
Вместо 6 вызовов `MapScene` (3 оси × 2 стороны) используем 4 вызова по
вершинам тетраэдра:
```glsl
return normalize(
    k.xyy * MapScene(p + k.xyy * e).x +
    k.yyx * MapScene(p + k.yyx * e).x +
    k.yxy * MapScene(p + k.yxy * e).x +
    k.xxx * MapScene(p + k.xxx * e).x
);
```
Экономия 33% на расчёте нормали.

### Оптимизация 8: RayMarchCoarse для преломления
Облегчённая версия `RayMarchCoarse` — 30 шагов вместо 60 (вдвое быстрее),
используется только для преломлённого прохода внутри капель, где точность
не критична (маленькая область экрана). Снижает стоимость пикселей внутри
капель примерно в 2 раза.

### Оптимизация 9: Упрощённый StarField
Один hash вместо нескольких — визуально похожий результат, меньше sin/cos.

## Устранение проблем

| Проблема | Что делать |
|----------|------------|
| `cl.exe` not found | Открой не обычный cmd, а "x64 Native Tools Command Prompt for VS 2022" |
| `g++` not found | Установи MinGW-w64 и добавь его bin-папку в PATH |
| Чёрный экран | Обнови драйверы GPU; проверь, что GPU поддерживает OpenGL 3.3+ |
| Шейдер не компилируется | В OutputDebugString будет лог ошибки — посмотри через DebugView (https://learn.microsoft.com/sysinternals/downloads/debugview) |
| Зум не работает колесом | Убедись, что окно в фокусе (кликни в него). Клавиши `+`/`-` всегда работают |
| Слишком медленно | В шейдере уменьши `8` в цикле частиц и `80` в `RayMarch` |

## Лицензия-заметка: почему так "мало" кода?

Весь "реальный" движок демо (raymarching, освещение, SDF, частицы)
уместился в одном фрагментном шейдере — это и есть философия демосцены:
**максимум визуального эффекта на минимум байт**. Современные 4K-интро
работают точно так же — один fullscreen quad + один шейдер, и магия
происходит в GPU. Наш main.cpp делает только "обвязку": создать окно,
GL-контекст, передать `uTime`, `uResolution` и `uZoom` в шейдер,
нарисовать quad. Остальное — на GPU.

Удачи в экспериментах!
